How to find EU public contracts that expire in the next 12 months

Pull expiring EU public contracts from TED award notices with Python: incumbent, buyer, value, end date and CPV code, ready for a bid pipeline.

Published 2026-10-01 · uses the TED Contract Expiry Radar - Recompete Leads Actor

Public buyers in Europe re-tender service contracts every few years. Cleaning, IT support, ticketing software, waste collection: the contract runs its term, then the authority publishes a new call for tenders and the incumbent defends its position.

The supplier that wins a recompete is rarely the one that reads the new tender on publication day. It is the one that knew a year earlier which contracts were ending and talked to the buyer in time. Bid managers, public-sector sales teams and consultancies that track competitors all need the same list: which contracts in my sector end in the next 6 to 18 months, who holds them and who buys them.

The data to build that list is public. Getting it into a spreadsheet is the hard part.

Where the data comes from

Buyers in the EU member states and several other European countries publish contract award notices on TED (Tenders Electronic Daily), the EU's official tender portal, which has a public search API at api.ted.europa.eu/v3/notices/search. An award notice names the buyer, the winning supplier, the awarded value, the CPV classification and usually how long the contract runs.

In practice, building an expiry list from that API runs into several problems:

  • Most notices do not state an end date. They state a duration ("36 months"), so you have to compute the end date yourself, from a start date that is not always there.
  • Per-lot fields are lists that do not line up. End dates, durations, titles and CPV codes come as parallel lists that can differ in order (one notice had results ordered 2-1-4-3) and length (48 results, 46 lots, 45 end dates). Matching by position silently attaches another lot's date.
  • Conclusion dates belong to contracts, not lots. TED lists the date each contract was signed, but does not say which contract covers which lot.
  • Query limits. One query can read at most 15,000 notices, and 11 of the 24 queries of a 12-month window match more, so the window has to be split.
  • Rate limits. TED answers HTTP 429 after roughly a dozen unpaced requests.

The TED Contract Expiry Radar Actor on Apify handles these. It reads the window in monthly slices, splits any slice above 15,000 notices into shorter date windows, paces requests at about one per second, and matches every per-lot field to its lot by the lot identifier. A list is only used when it has exactly one entry per lot; otherwise the field stays empty rather than guessed. When an end date is missing, it is computed from the lot start date or from an unambiguous conclusion date plus the published duration, and every row says which method was used.

Step by step

1. Define the input

All fields are optional. A realistic input for an IT services company looking at Germany and France, skipping contracts that end in under three months:


{
  "queries": ["software"],
  "countries": ["DE", "FR"],
  "cpvPrefixes": ["72"],
  "incumbents": [],
  "expiresAfterMonths": 3,
  "expiresBeforeMonths": 15,
  "minValue": 100000,
  "includeFrameworkAgreements": true,
  "estimateMissingEndDates": true,
  "maxItems": 200
}

Details:

  • countries takes two-letter codes; the output uses three-letter ISO codes (DEU, FRA).
  • queries are checked per lot: a lot is returned only if a keyword appears in its own title or description, or in the contract or notice title, in the language of the notice. A German notice will not match software unless the word appears in it, so add local terms when needed.
  • minValue is compared in the contract's own currency, without conversion.
  • incumbents matches a word in the winning supplier's name.

2. Run it from Python


from apify_client import ApifyClient

client = ApifyClient("YOUR_APIFY_TOKEN")

run_input = {
    "queries": ["software"],
    "countries": ["DE", "FR"],
    "cpvPrefixes": ["72"],
    "expiresAfterMonths": 3,
    "expiresBeforeMonths": 15,
    "minValue": 100000,
    "maxItems": 200,
}

run = client.actor("datagrit/ted-contract-expiry-radar").call(run_input=run_input)

for item in client.dataset(run["defaultDatasetId"]).iterate_items():
    if item.get("found"):
        print(item["contractEnd"], item["buyerName"], item["incumbentName"], item["awardValue"])

curl -X POST \

The synchronous endpoint suits small, filtered runs. An unfiltered 12-month window matched about 251,000 notices on 30 September 2026 and took roughly 45 minutes, so start large runs asynchronously, as in the Python example. Results come soonest-expiry first, so a maxItems cap returns the most urgent contracts and stops early.

Market sizing in pandas


import pandas as pd

df = pd.DataFrame([i for i in client.dataset(run["defaultDatasetId"]).iterate_items() if i.get("found")])

eur = df[df["currency"] == "EUR"]  # values are not converted between currencies
summary = (
    eur.groupby(["buyerCountry", "cpvCode"])
       .agg(lots=("id", "count"), value_eur=("awardValue", "sum"), median_months=("contractLengthMonths", "median"))
       .sort_values("value_eur", ascending=False)
)
print(summary.head(20))

# Share of rows whose end date was computed rather than stated
print(df["endDateSource"].value_counts(normalize=True))

Limitations

  • Only awarded contracts. Open tenders and planned procurements are not covered.
  • Computed end dates ignore extensions and early termination. Treat start+duration and award+duration rows as strong leads, and switch estimateMissingEndDates off if you need only dates the buyer stated.
  • Some durations are not searched. For computed dates the Actor queries common durations (3 to 120 months in common steps, 1 to 8 and 10 years). Other lengths, or durations in days or weeks, appear only with a stated end date; in a sample of 2023 notices that left out about 7 percent of notices with a duration.
  • Ambiguous lots stay empty. When winners or per-lot fields cannot be matched safely, incumbentName or the date stays empty instead of guessed, and such a lot may not appear in the window at all.
  • Run time on wide windows. At about one request per second, an unfiltered 12-month window takes tens of minutes. A narrower window, a country or CPV filter, or a maxItems cap shortens it.
  • A run where TED returns awarded lots with no end dates or durations at all fails on purpose, so a source change is not mistaken for "no expiring contracts".

The data is what the EU publishes openly on TED; the Actor does not log in or bypass access controls.
